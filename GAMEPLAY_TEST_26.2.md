# Player Collars 1.6.1+26.2 Windows Regression Checklist

Use Minecraft 26.2, Fabric Loader 0.19.3, Fabric API 0.155.2+26.2,
Trinkets Updated 4.1.0-beta.3+26.2, and Java 25. Test with only these mods
first. Keep `latest.log` from both client and server for every failure. Back up
all 26.1.2 worlds and player data before opening them in 26.2.

For multiplayer ownership tests, use two accounts: **Owner** and **Pet**. Creative
mode and `/give` are recommended for setup. Item IDs remain under
`playercollars`; for example, `/give @s playercollars:collar`.

## Highest-risk migration checks

| # | Test and concrete steps | Expected result | Failure evidence and logs |
|---|---|---|---|
| 1 | **Client startup.** Launch the Fabric 26.2 profile with the required dependencies and this JAR. Wait for the title screen. | The title screen appears; the Mods list shows Player Collars 1.6.1+26.2 and Trinkets Updated. | Record loader dependency errors, missing Mixin targets, access-widener failures, `NoClassDefFoundError`, and the complete client `latest.log`. |
| 2 | **Fresh single-player world.** Create a new Creative world, enter it, open inventory, and run `/give @s playercollars:collar`. | World and datapacks load; the item exists with its expected name and texture. | Look for registry freeze errors, failed recipes/tags, missing item models, datapack validation errors, or a disconnect during world creation. |
| 3 | **Dedicated server and join.** Start a clean Fabric 26.2 server with the same dependencies and JAR, wait for `Done`, then join from the client. | Server reaches `Done`; client joins without registry or network-channel mismatch. | Capture both logs. Check for payload registration errors, “unknown registry entry,” Mixin failures, client-only classes on the server, or login disconnect reasons. |
| 4 | **Trinkets necklace slot.** Open the Trinkets UI, place a normal collar in the chest/necklace slot, close and reopen the UI, then remove it. | The slot accepts the collar, preserves the stack, and allows removal when not locked. | Watch for rejected slots, duplicated/lost stacks, attachment errors, or `trinkets_updated` stack traces. |
| 5 | **Ownership contract.** Owner right-clicks a blank Deed of Ownership to fill it, gives it to Pet, and Pet opens and stamps it. Craft/use the stamped deed with a collar according to its recipe, then equip the collar on Pet. | The collar tooltip/name identifies Owner and Pet correctly; ownership survives moving the item and equipping it. Self-ownership is rejected. | Check for missing `owner_component`, packet errors from deed stamping, wrong UUID/name, forged-deed messages, or data loss after inventory changes. |
| 6 | **Owner Control Panel.** With Owner and owned Pet nearby, use the collar/owner interaction that opens the control panel. Toggle movement, speech, vision, commands, and forced crawl one at a time. | Only Owner can open/change Pet’s controls; labels update immediately and each setting affects Pet. | Test a third non-owner too. Record “not owner/too far/invalid request” messages, stale GUI state, packet codec errors, or settings that affect the wrong player. |
| 7 | **Player leash.** Owner leashes collared Pet, walks through short and long distances, changes direction, and crosses a chunk boundary. | A leash renders between players; Pet is pulled according to current rules without teleport loops, proxy turtles, particles, or hitboxes becoming visible. | Check server log for leash proxy exceptions, recursive movement packets, entity ticking errors, or unexpected disconnects. |
| 8 | **Fence tie, anchor hiding, and release.** While Pet is leashed, use a fence to tie the leash, inspect from several angles and in F3+B, then release it through the intended interaction. Also ask a non-owner to break the knot. | Pet stays tied; the hidden proxy/anchor is not visible or normally targetable; permitted release works; unauthorized break is blocked with the expected message. | Look for visible turtle/anchor entities, broken fence interaction, orphan knots after release, `LeashFenceKnotEntity` Mixin errors, or Pet remaining pulled after release. |
| 9 | **Server restart persistence.** Leave Pet collared, owned, configured, and fence-tied. Stop the server with `stop`, restart it, and rejoin both accounts. | Collar equipment, owner UUID/name, controls, leash state where supported, and world blocks reload without corruption or duplication. | Save both shutdown/startup logs. Check component decode errors, missing entity references, lost Trinkets attachment data, or chunk/entity load failures. |
| 10 | **26.1.2 data compatibility.** On a backup copy, first load a 26.1.2 test world/player with owned and dyed collars, paws, bowls, beds, fences, locker state, and enchantments. Then open the copy in 26.2. | Existing registered items/blocks remain recognized; item components, owner data, equipped stacks, colors, enchantments, and world blocks load. | Never overwrite the only backup. Record DataFixer/component codec errors, “unknown item/block,” replaced blocks, empty Trinkets slots, or reset owner UUIDs. |
